# bonoxauto

Telegram-бот для автопокупок на [bonoxs.com](https://bonoxs.com) по расписанию: пополнение игр,
алмазы, подписки и т. п. Вы один раз задаёте, что купить, на какой аккаунт, не дороже какой суммы
и когда, — дальше бот покупает сам и присылает отчёт.

> **Статус.** Сам бот готов и проверен на демо-магазине: расписания, лимиты, dry-run, история,
> ожидание оплаты, управление из Telegram. **Адаптер bonoxs.com ещё не подключён к сайту** —
> см. раздел [«Подключение bonoxs.com»](#подключение-bonoxscom). Пока в нём нет реальных запросов,
> бот работает с тестовым каталогом (`SHOP=demo`).

## Что умеет

- **Задачи**: товар и пакет, Player ID (и Server ID, если игра его требует), лимит цены, расписание.
- **Расписания**: ежедневно, по дням недели, ежемесячно, разово — в вашем часовом поясе.
- **Деньги под контролем**: лимит цены в каждой задаче, дневной и месячный бюджет по валюте.
- **Dry-run по умолчанию**: бот проверяет цену и лимиты и пишет, что купил бы. Реальные покупки
  включаются командой `/mode` с подтверждением.
- **Без двойных покупок**: каждый запуск обрабатывается один раз, а заказ никогда не повторяется
  автоматически. Если непонятно, прошёл ли заказ (обрыв связи, перезапуск), бот пометит покупку
  «результат неизвестен», учтёт её в бюджете и попросит проверить сайт.
- **Бот был выключен**: при опоздании до `MISFIRE_GRACE_MINUTES` (по умолчанию 15 минут) покупка
  выполнится сразу после запуска бота. При большем опоздании запуск отметится как пропущенный,
  и придёт сообщение.
- **Оплата Pix/boleto**: если магазин требует оплату, бот пришлёт код или ссылку, дождётся оплаты,
  а затем зачисления.
- **Только для вас**: бот отвечает только Telegram ID из `ADMIN_IDS`.

## Быстрый старт

Нужен Python 3.11 или новее.

1. Создайте бота у [@BotFather](https://t.me/BotFather) и скопируйте токен.
2. Узнайте свой Telegram ID, например у [@userinfobot](https://t.me/userinfobot).
3. Скопируйте `.env.example` в `.env` и заполните `BOT_TOKEN`, `ADMIN_IDS` и `TIMEZONE`.
4. Установите и запустите:

   ```bash
   python -m venv .venv
   source .venv/bin/activate        # Windows: .venv\Scripts\activate
   pip install .
   python -m bonoxauto
   ```

5. Напишите боту `/start`, потом `/add`. В демо-магазине на вопрос о товаре отправьте
   `free-fire` или `mobile-legends`.

### Docker (для сервера)

```bash
cp .env.example .env   # заполните
docker compose up -d --build
docker compose logs -f
```

База данных лежит в `./data` и не пропадает при пересборке.

## Команды

| Команда | Что делает |
|---|---|
| `/add` | Новая задача: товар → пакет → аккаунт → лимит цены → расписание → оплата |
| `/tasks` | Список задач. В карточке задачи: пауза, «купить сейчас», изменить расписание или лимит, удалить |
| `/history` | Последние запуски и их итог (`/history 30` покажет больше) |
| `/status` | Магазин, режим, ближайшие запуски, расходы |
| `/mode` | Переключение dry-run и реальных покупок |
| `/limits` | Бюджет и расходы. Задать лимит: `/limit день BRL 50`, `/limit месяц BRL 300`, снять: `/limit день BRL off` |
| `/pause`, `/resume` | Остановить или возобновить все автопокупки. Запуски, пришедшиеся на паузу, не выполняются |
| `/cancel` | Отменить ввод |

## Расписания

| Пример | Значение |
|---|---|
| `ежедневно 12:00` | каждый день в 12:00 |
| `ежедневно 09:00, 21:00` | дважды в день |
| `пн, чт 18:30` | по понедельникам и четвергам |
| `пн-пт 10:00` или `будни 10:00` | по будням (`выходные 11:00` — по выходным) |
| `ежемесячно 1 10:00` | 1-го числа каждого месяца; `ежемесячно 1, 15 10:00` — дважды в месяц |
| `разово 10.11.2026 12:00` | один раз |

Английские варианты тоже понимаются: `daily 12:00`, `mon,thu 18:30`, `monthly 1 10:00`,
`once 2026-11-10 12:00`. Если в месяце нет указанного числа (31-е в ноябре), покупка будет
в последний день месяца.

## Как проходит покупка

1. В назначенное время бот открывает товар и смотрит текущую цену пакета.
2. Покупка **пропускается**, если пакета нет в наличии, цена выше лимита задачи, бюджет на день
   или месяц исчерпан или включена пауза.
3. В **dry-run** бот только присылает сообщение «купил бы за …».
4. В **боевом режиме** бот оформляет заказ один раз. Если магазин просит оплату, бот присылает код
   и ждёт её `PAYMENT_TIMEOUT_MINUTES`, затем ждёт зачисления.
5. Итог приходит сообщением и попадает в `/history`.

| Значок | Статус |
|---|---|
| ✅ | куплено |
| 💳 | заказ создан, нужна оплата |
| 🚚 | оплачено, ждём зачисления |
| 🧪 | dry-run: купил бы |
| ⏭ | пропущено (цена, бюджет, наличие, пауза) |
| ⏰ | пропущен запуск: бот был выключен |
| ❌ | не куплено, деньги не списаны |
| ⌛ | оплата не поступила вовремя |
| ❓ | результат неизвестен: проверьте заказы на сайте |

## Подключение bonoxs.com

Что известно из открытых источников: сайт разделён по регионам (`/br/`, `/mx/`, `/ar/`, `/co/`
и другие), у каждой игры своя страница (например, `https://bonoxs.com/br/free-fire`). Покупка
идёт по Player ID, для некоторых игр нужен ещё Server ID. Оплата — Pix, карта, boleto и
региональные способы. Вход — по email и паролю или через Google. Публичного API нет.

Из среды, где писался бот, сайт был недоступен: сеть ограничена. Поэтому реальные запросы ещё
не написаны, и `bonoxauto/shop/bonoxs.py` пока отвечает ошибкой «адаптер не подключён». Чтобы его
доделать, нужно одно из двух:

- **открыть доступ к `bonoxs.com`** в сетевых настройках окружения Claude Code (Network access →
  Allowed domains) — тогда сайт можно изучить напрямую;
- **или прислать HAR-файл** с реальной покупкой: откройте bonoxs.com в браузере → F12 → вкладка
  Network → включите «Preserve log» → войдите в аккаунт, откройте страницу игры, введите Player ID,
  дойдите до оплаты (платить не обязательно) → правый клик → «Save all as HAR».
  ⚠️ В HAR-файле есть cookies и токены входа. Удалите их перед отправкой или смените пароль после.

Адаптеру нужно реализовать четыре метода (контракт описан в `bonoxauto/shop/base.py`):
`get_product` (пакеты и цены), `check_account` (проверка Player ID), `place_order` и `get_order`.

**Про оплату.** Полностью автоматическая покупка возможна, если оплата не требует вашего участия:
баланс на сайте или сохранённая карта без подтверждения. С Pix или boleto бот создаст заказ
по расписанию и пришлёт код — останется оплатить в банковском приложении.

Перед использованием проверьте правила bonoxs.com: автоматизация покупок может ими ограничиваться.

## Разработка

```bash
pip install -e ".[dev]"
pytest
ruff check . && ruff format --check .
```

| Модуль | Назначение |
|---|---|
| `bonoxauto/schedule.py` | разбор расписаний и расчёт следующего запуска (часовые пояса, переход на летнее время) |
| `bonoxauto/engine.py` | покупка: проверки, лимиты, dry-run, заказ, ожидание оплаты, восстановление после перезапуска |
| `bonoxauto/scheduler.py` | планировщик: время следующего запуска хранится в БД, пропуски при простое |
| `bonoxauto/storage.py` | SQLite: задачи, история, настройки |
| `bonoxauto/shop/` | интерфейс магазина, демо-магазин, заготовка адаптера bonoxs.com |
| `bonoxauto/bot/` | Telegram-интерфейс (aiogram 3) |
